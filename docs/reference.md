# Annota reference

> Generated by `annota ide docs`. Do not edit by hand: change the registries in
> `src/analyzer.cpp` (annotations / checks), `src/builtins.cpp` (file primitives) and
> `src/sys_api.cpp` (system primitives).
>
> The descriptions below are the strings the tool itself shows, so they are in Chinese;
> identifiers (annotation names, diagnostic codes, primitives) are stable ASCII.

## 1. Annotations

Annotations are the specification language: the analyzer assumes `[[require]]` at the
function entry, checks it at every call site, and so on. Write them on the unit they
describe (a statement, a function, a loop, or the file itself).

| Annotation | Category | Scopes | Arguments | Meaning |
|---|---|---|---|---|
| `[[ignore]]` | 分析控制 | any | 0..16 + kwargs | 忽略下一单元的分析 |
| `[[assume]]` | 分析控制 | stmt \| func \| loop \| block \| any | 1 | 分析时假设条件成立 |
| `[[assert]]` | 分析控制 | stmt \| func \| loop \| block \| any | 1 | 分析时断言条件成立 |
| `[[unreachable]]` | 分析控制 | stmt \| any | 0..1 | 标记不可达代码 |
| `[[propagate]]` | 分析控制 | stmt \| func \| any | 1 | 把本标注传播到函数 |
| `[[unsafe]]` | 安全与信任 | func \| stmt \| any | 0..1 + kwargs | 标记不安全代码 |
| `[[trusted]]` | 安全与信任 | func \| any | 0..1 | 信任此函数并跳过函数体分析 |
| `[[pure]]` | 安全与信任 | func \| any | 0 | 无副作用 |
| `[[noreturn]]` | 安全与信任 | func \| any | 0 | 函数不会正常返回 |
| `[[jit]]` | 性能 | func \| any | 0 | 加载期优化这个函数 |
| `[[require]]` | 契约 | func | 1 | 前置条件 |
| `[[ensure]]` | 契约 | func | 1 | 后置条件 |
| `[[invariant]]` | 契约 | loop | 1 | 循环不变量 |
| `[[decrease]]` | 契约 | loop | 1 | 终止度量 |
| `[[modifies]]` | 契约 | func | 1 | 允许修改的对象 |
| `[[module]]` | 元信息 | file \| any | 1 | 模块名 |
| `[[version]]` | 元信息 | file \| any | 1 | 版本号 |
| `[[author]]` | 元信息 | file \| any | 1 | 作者 |
| `[[macro_depth]]` | 元信息 | file \| any | 1 | 宏展开深度上限 |
| `[[doc]]` | 元信息 | any | 1 | 文档字符串 |
| `[[deprecated]]` | 元信息 | any | 1 | 弃用提示 |
| `[[todo]]` | 元信息 | any | 1 | 待办 |
| `[[analyzer]]` | 分析器 | file \| any | 1 | 指定分析器 |
| `[[rule]]` | 分析器 | file \| any \| func | 2..3 | 开关规则 |
| `[[complexity]]` | 分析器 | func \| file \| any | 1 | 循环复杂度上限 |
| `[[max_memory]]` | 分析器 | func \| file \| any | 1 | 内存上限 |
| `[[max_time]]` | 分析器 | func \| file \| any | 1 | 时间上限 |
| `[[taint]]` | 分析器 | stmt \| func \| any | 1 | 污点源 |
| `[[expose]]` | 可见性 | class \| file \| any | 1..16 | 暴露给 GUI |
| `[[private]]` | 可见性 | field \| func \| class | 0 | 私有成员 |
| `[[public]]` | 可见性 | field \| func \| class | 0 | 公有成员 |
| `[[static]]` | 可见性 | field \| func | 0 | 静态成员 |
| `[[backend]]` | 后端 | file \| func \| any | 1 | 生成目标 |

Details:

* `[[ignore]]` - 忽略下一单元的分析 不带参数忽略全部分析；带检查名只忽略该检查；可再跟原因与 severity。
* `[[assume]]` - 分析时假设条件成立 把条件加入当前抽象状态（例如缩小 range），不会生成运行期代码。
* `[[assert]]` - 分析时断言条件成立 在当前位置检查条件；可证明为假时报错，无法判定时给出 warning。
* `[[unreachable]]` - 标记不可达代码 声明该位置本就不可达，从而关闭死代码检查。
* `[[propagate]]` - 把本标注传播到函数 [[propagate: f]] 表示把当前单元的标注语义传播给函数 f。
* `[[unsafe]]` - 标记不安全代码 常用于 FFI 边界；带原因的 unsafe 会降低相关诊断的严重度。
* `[[trusted]]` - 信任此函数并跳过函数体分析 整段跳过函数体的数据流分析，require 只作为文档保留。
* `[[pure]]` - 无副作用 禁止写全局、写字段、调用非纯函数。
* `[[noreturn]]` - 函数不会正常返回 通常内部 throw 或无限循环；与 ensure: result... 冲突。
* `[[jit]]` - 加载期优化这个函数 编译时对该函数做常量折叠与超指令融合（后续的机器码后端挂在同一个标记下）。
* `[[require]]` - 前置条件 函数入口假定成立；在每个调用点检查实参是否满足。
* `[[ensure]]` - 后置条件 函数出口检查；可用 result 引用返回值。
* `[[invariant]]` - 循环不变量 在循环入口、每次迭代末尾检查；只作用于循环。
* `[[decrease]]` - 终止度量 要求表达式在每次迭代严格递减且迭代前为正。
* `[[modifies]]` - 允许修改的对象 声明副作用范围；被调函数修改范围之外的对象会被报告。
* `[[module]]` - 模块名 文件级元信息。
* `[[version]]` - 版本号 文件级元信息。
* `[[author]]` - 作者 文件级元信息。
* `[[macro_depth]]` - 宏展开深度上限 解析阶段生效，超出即报 Macro expansion depth exceeded。
* `[[doc]]` - 文档字符串 悬停时显示。
* `[[deprecated]]` - 弃用提示 替代方案写在参数里。
* `[[todo]]` - 待办 不参与分析，仅登记。
* `[[analyzer]]` - 指定分析器 例如 polyspace；本实现接受并记录。
* `[[rule]]` - 开关规则 [[rule: MISRA-C 8.1, on]] / off。
* `[[complexity]]` - 循环复杂度上限 超过上限时给出 info。
* `[[max_memory]]` - 内存上限 记录用；本实现不做内存建模。
* `[[max_time]]` - 时间上限 记录用。
* `[[taint]]` - 污点源 该处产生的值被标记为污染，传播到 [[unsafe]] 处报告。
* `[[expose]]` - 暴露给 GUI 列出暴露给界面层的名字。
* `[[private]]` - 私有成员 类成员默认私有。
* `[[public]]` - 公有成员 顶层默认公有。
* `[[static]]` - 静态成员 字段或方法属于类本身。
* `[[backend]]` - 生成目标 dafny / lean / c / webgl，可叠加。

## 2. Diagnostic codes

Every message the analyzer emits carries a stable code. Use it in
`[[ignore: <code>]]` to suppress one check, and in tooling to map diagnostics.
The human readable messages are Chinese; the codes and severities are English.

| Code | Meaning |
|---|---|
| `syntax-error` | 语法错误 |
| `bracket-mismatch` | 括号 / 块没有正确闭合 |
| `unknown-annotation` | 标注不在注册表中，也不是模块用 macro 注册的 |
| `annotation-scope` | 标注用在了不允许的位置（如把 [[invariant]] 写在函数上） |
| `annotation-conflict` | 两个标注语义冲突（如 [[pure]] 与 [[modifies]]） |
| `annotation-argument` | 参数个数或取值非法（如 severity 不是 low/medium/high/critical） |
| `unknown-check` | [[ignore]] 里写了不存在的检查名 |
| `duplicate-annotation` | 同一个标注重复出现 |
| `uninitialized` | 读取未初始化或未声明的变量 |
| `unused-variable` | 变量 / 参数声明后从未被读取 |
| `unreachable` | 控制流不可达的代码 |
| `division-by-zero` | 除数为 0，或可能为 0 |
| `overflow` | 整数运算超出目标宽度（默认按 32 位判定） |
| `out-of-bounds` | 索引超出序列长度范围 |
| `null-dereference` | 对 null（或可能为 null）的值取成员 / 下标 / 调方法 |
| `contract-violation` | 调用点可以证伪被调函数的 [[require]] |
| `contract-possible` | 调用点无法判定被调函数的 [[require]] |
| `ensure-violation` | 函数出口可以证伪 [[ensure]] |
| `invariant-violation` | 循环不变量在入口不成立，或迭代后不再成立 |
| `termination` | [[decrease]] 度量不是正数或没有严格递减 |
| `purity` | [[pure]] 函数里出现副作用（写全局 / 写字段 / print / 调用非纯函数） |
| `taint` | 被 [[taint]] 标记的数据流入 [[unsafe]] 区域 |
| `dead-store` | 赋值之后从未被读取就被覆盖 |
| `infinite-loop` | 条件恒为真且循环体没有退出路径 |
| `type-mismatch` | 声明类型、运算符、比较或 for 的可迭代性不匹配 |
| `iterator-misuse` | 把 (1 to 10) 迭代器当作普通值使用 |
| `macro-side-effect` | 宏体重复展开含函数调用的实参，可能重复副作用 |
| `redundant-condition` | 条件在当前抽象状态下恒真或恒假 |
| `scope` | 读取已经结束的裸作用域里的变量 |
| `except-placement` | except 没有跟在块的最后 |
| `assert-violation` | [[assert]] 可以证伪 |
| `assert-unproven` | [[assert]] 无法证明（分析器精度不足） |

## 4. Primitive ABI

C++ exposes only thunks over the operating system; every convenience API lives in
`lib/*.mod` and is written in Annota, so new features usually mean a new module rather
than a rebuild. The same primitives are reachable through the `system` facade
(`system.clock()`, `system.call("clock")`, `system.primitives()`).

| Primitive | Returns | Meaning |
|---|---|---|
| `_sys_clock()` | int | monotonic milliseconds (measure elapsed time) |
| `_sys_time()` | int | wall clock milliseconds since the epoch |
| `_sys_sleep(ms)` | null | sleep |
| `_sys_local_time([ms])` | List | `[year, month, day, hour, minute, second, weekday]` |
| `_sys_make_time(y, mo, d[, h, mi, s])` | int | local time to a timestamp (ms) |
| `_sys_info(key)` | String/int | `platform`, `arch`, `cpus`, `pid`, `home`, `temp`, `cwd` |
| `_sys_env(name)` | String/null | environment variable |
| `_sys_env_set(name, value)` | bool | set for this process and its children |
| `_sys_env_all()` | List | `[[name, value], ...]` |
| `_sys_exec(cmd)` | List | `[exitCode, output]`, run through the shell |
| `_sys_spawn(fn[, args])` | int | run `fn(...)` on a worker thread, returns a task handle |
| `_sys_task_done(handle)` | bool | has the worker finished? |
| `_sys_join(handle)` | value | wait and return the result (rethrows worker errors) |
| `_sys_socket(op, ...)` | varies | `resolve`, `connect`, `listen`, `accept`, `send`, `recv`, `close`, `shutdown`, `timeout` |

Built on top of them: `lib/time.mod`, `lib/os.mod`, `lib/thread.mod`, `lib/net.mod`.
The clock is also available directly as `time.now()` (seconds), `time.millis()` (wall
milliseconds), `time.clock()` (monotonic milliseconds) and `time.sleep(ms)`.

## 5. Commands

```
annota                       REPL (also the default with no arguments)
annota studio [file]         graphical IDE (Qt build)
annota run|check <file>      execute / parse only
annota analyze <file>        static analysis (--json, --level, --int-bits, --modules)
annota analyze-suite <dir>   run the checker over fixtures
annota ide <query> ...       hover, definition, rename, complete, inline,
                             coverage, quickfix, suppressions, report,
                             checks, annotations, docs
annota bench                 analysis performance benchmark
annota lsp                   language server (stdio, JSON-RPC)
```
