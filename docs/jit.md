# `[[jit]]`：提前优化

`[[jit]]` 只表达一件事：**这段代码值得在加载时优化**。它不改变语义——同一个函数带标记和不带标记，
结果（包括 `typeof`）必须完全一致，见 `examples/jit.ant`。

```annota
[[jit]]
sum_to(n)(
    new s = 0
    new i = 0
    while i < n(
        s = s + i
        i = i + 1
    )
    =s
)
```

解释器在加载时对这个函数做两件事：

## 1. 超指令融合（总是进行）

融合保持字节码长度不变（空出来的位置填 `nop`），所以所有跳转目标仍然有效：

| 原序列 | 融合为 |
| --- | --- |
| `s = s + k` | `local+=` |
| `s = s - k` | `local-=` |
| `s = s + t` | `local+=local` |
| `i < n` + 条件跳转 | `local<local?` |
| `i < k` + 条件跳转 | `local<imm?` |
| `a[i] = a[i] + k` | `index+=` |

## 2. 机器码后端（整个函数可翻译时）

如果函数体全部落在整数子集里，整个函数会被翻译成 x86-64 机器码，调用时直接执行原生代码：

- 允许的指令：局部变量读写、整数加减乘、六种比较、条件跳转、无条件跳转/回跳、返回；
- 整数运算直接在当前栈槽上完成（虚拟寄存器在原生栈帧里），没有逐条指令的派发开销；
- **参数与未确定赋值的局部变量在调用前检查**：不是整数就照常解释执行，语义不变；
- 返回值的类型（`int` / `int64` / `bool`）用运行期种类字节记录，因此 `typeof` 与解释器一致。

翻译不了的情况（字符串、列表、调用、闭包、循环外的递归、无法证明类型的运算……）会安静地退回解释器，
所以标记永远不会让程序出错。

## 3. 安全开关

```powershell
$env:ANNOTA_NO_JIT = "1"      # 关闭机器码后端，只保留融合
$env:ANNOTA_JIT_DEBUG = "1"   # 打印某个函数为什么没被翻译
```

## 4. 实测

同一台机器，`examples/perf.ant` 与 `examples/jit.ant`：

| 工作 | 解释器 | `[[jit]]` |
| --- | --- | --- |
| `while` 循环 40 万次 | 69 ms | 不到 1 ms |
| 10 次加法循环体 30 万次 | 192 ms | 1 ms |

`examples/perf.ant` 里对应的两行就是"同一个函数、有没有标记"的对照。

## 5. 什么时候该用哪条路线

| 情况 | 建议 |
| --- | --- |
| Annota 里的纯整数循环 | `[[jit]]` |
| 算法内核（排序、筛法、矩阵……） | 链接 C++，见 [FFI](ffi.md) |
| 只是写法啰嗦、想复用 | 标准库脚本模块（`lib/*.mod`） |
