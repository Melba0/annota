# Annota 语法规范

本文件是 Annota 的语法参考：词法、语句、表达式、类型与预定义结构。工具链实现与本文不一致时，
以本文为准并视为 bug。标注、诊断码与底层原语的完整清单见
[reference.md](reference.md)（由 `annota ide docs` 生成）。

想在浏览器里对照代码阅读，可先看 [style.md](style.md)（代码规范）。

---

## 1. 源文件

* 编码 **UTF-8**（允许 BOM）。换行 `\n`，`\r` 被忽略。
* 一个文件就是一个**脚本**：顶层语句按书写顺序执行，**没有 `main` 函数**。声明必须先于使用
  （函数/类体内的引用在调用时才解析，因此递归与相互调用是允许的）。
* 文件可以 `use` 其它模块（见 §9）。

### 1.1 注释与分段

| 形式 | 含义 |
|---|---|
| `-- 到行尾` | 行注释 |
| `-[ ... ]-` | 块注释 / 文件头说明（可跨行） |
| `—分段 名称` | 行首的特殊标记，仅作视觉分段，等价于注释 |

```annota
-[ 文件级说明，通常放在最前面 ]-
-- 行注释

—分段 工具函数
```

### 1.2 续行与语句分隔

* 语句以**换行**结束。`;` **不是**分隔符（会报语法错误）。
* 同一行写多条语句用**逗号**：`a = 1, b = 2`（也支持 `new a, b`、`del a, b`）。
* 行尾是**二元运算符**（`+ - * / % ** & | ^ << >> && || == != < > <= >=`）、`=` 或 `.` 时，
  自动续到下一行；`\` 是显式续行符。`,` 结尾不自动续行（否则 `new a, b` 会有歧义）。

```annota
new total = 1 +
            2 +
            3              -- 6

new other = 1 + \
            2              -- 3
```

**必须同行的一处**：`else` 要紧跟 `if` 体结尾的 `)`。

```annota
if n > 0( print "positive" ) else ( print "other" )   -- ✓
if n > 0(
    print "positive"
) else (                                              -- ✓ `) else (` 在同一行
    print "other"
)
```

## 2. 词法

### 2.1 关键字

```
new  del  const  lend  macro  use  view  state
if  elif  else  for  while  in  break  continue
throw  except  print  input
true  false  null  this  super
```

`elif` 只是 `else if` 的写法，解析时等价于 `else` 里再套一个 `if`（见 §4.3）。
`lend` 是引用声明（见 §4.1.2）。

`to` 与 `step` 是**软关键字**：只在 `a to b [step c]` 这个位置有特殊含义，因此可以当普通
变量名/参数名使用（`File.copy(from, to)`）。

### 2.2 字面量

| 字面量 | 例 |
|---|---|
| 整数 | `42`、`-7`、`0xFF`、`0b1010`、`1_000_000` |
| 浮点 | `3.14`、`1e-9` |
| 字符串 | `"hello"`，转义 `\n \t \r \0 \\ \" \'`（未识别的转义原样保留） |
| 布尔 / 空 | `true`、`false`、`null` |
| 列表 | `[1, 2, 3]`、`[]` |
| 元组 | `(1, 2)`（逗号分隔，见 §5.6） |
| 字节串 | `Bytes(...)`、`_file_read_bytes(...)` |
| 颜色 | `Color(...)` |

> 字符串是**字节串**：`len("世界")` 为 6，索引按字节。

### 2.3 命名

标识符由字母、数字、`_` 组成，不以数字开头；可含非 ASCII 字符（UTF-8）。约定见
[style.md](style.md)：`PascalCase` 用于类/组件，`snake_case` 用于函数与变量，`UPPER_SNAKE`
用于常量，`_` 前缀表示底层原语（用户代码不直接用，改用 `lib/` 封装）。

## 3. 运算符与优先级

从低到高：

| 级别 | 运算符 | 结合性 |
|---|---|---|
| 1 | `\|\|` | 左 |
| 2 | `&&` | 左 |
| 3 | `\|` | 左 |
| 4 | `^` | 左 |
| 5 | `&` | 左 |
| 6 | `==` `!=` | 左 |
| 7 | `<` `>` `<=` `>=` | 左 |
| 8 | `<<` `>>` | 左 |
| 9 | `+` `-` | 左 |
| 10 | `*` `/` `%` | 左 |
| 11 | `**` | 右 |
| 12 | 前缀 `-` `!`（`not`）`~`，后缀 `(...)` `[...]` `.name` | — |

要点：

* **`/` 与 C 对齐**：两侧都是整数时**向零截断**（`7 / 2` → `3`，`-7 / 2` → `-3`）；
  任一侧是 `float`/`double` 才做浮点除法（`7 / 2.0` → `3.5`）。取余用 `%`（符号随被除数）。
  想要小数结果就显式写浮点：`float(a) / float(b)` 或 `a / 2.0`。
* `&&` / `||` 短路求值。
* `a to b`（可带 `step c`）构造**迭代器**，只能用于 `for`（见 §4.4）。
* 复合赋值：`+= -= *= /= %= **= &= |= ^= <<= >>=`。

## 4. 语句

### 4.1 声明与赋值

```annota
new a = 1                  -- 声明并初始化
new b, c                   -- 一次声明多个（未初始化，读取会被分析器报告）
new x = 1, y = 2, z = 3    -- 各自带初值
const LIMIT = 100          -- 常量：不能再赋值，也不能 del
a = 2, b = 3               -- 同行多条赋值
state count = 0            -- GUI 响应式状态（view 内）
del a, b                   -- 删除（变量回到未初始化）
```

`new` 不写初值时，字段类型决定默认值（`int`→0、`float`→0.0、`bool`→false、`List`→`[]`、
其它→`null`）。

#### 4.1.1 值语义：赋值、传参、返回都是深拷贝

容器（`List`、`Map`、`Instance`、数组……）在**赋值、作为实参传递、以及作为函数返回值**时都会
深拷贝；数字、布尔、字符串是不可变值，可以共享。

```annota
new xs = [1, 2]
new ys = xs
ys.push(3)                 -- ys 是 [1, 2, 3]，xs 仍是 [1, 2]

new bucket = d.get(k)      -- 方法返回值同样是副本
bucket.push(x)             -- 改的是副本，d 里没变
d.set(k, bucket)           -- 想改容器里的内容就要写回
d.get(k).push(x)           -- 这样写等于什么都没做
```

例外与补充：

* 下标取值共享元素对象，所以 `xs[0].push(1)`、`m[i][j] = v` 这类写法是就地生效的；
* 闭包按引用捕获外层变量，所以闭包里改的是同一个变量；
* 需要**显式共享**时用 `lend`（下一节），这是值语义的对应出口。

#### 4.1.2 引用：`lend`

```annota
new xs = [1, 2, 3]
lend r = xs           -- r 和 xs 是同一份存储
r.push(4)             -- xs 也变成 [1, 2, 3, 4]
r[0] = 99             -- 通过任一名字写，另一个名字都看得到

new i = 1
lend j = i
j = 7                 -- i 也是 7
```

规则：

* `lend a = b` 的右边必须是**变量**（同一函数的局部变量，或全局变量）；表达式、常量、
  外层函数的局部变量都不行（这种会报错，因为引用只共享同一函数作用域内的存储）。
* 两个名字共享同一个存储单元：读、写、以及闭包捕获都作用在同一份数据上。
* 它只是"值语义 + 显式共享"：不写 `lend` 就仍然是深拷贝，所以不会意外互相影响。
* 典型用途：函数就地更新一个全局容器（省掉"取出—修改—写回"和整份拷贝）、给长表达式
  取个短名字并保持同步、需要两个名字看到彼此写入的场景。
* 静态分析器知道两个名字互为别名：读任一名字算读另一个，任一侧写入都会丢弃另一侧已推断
  出的取值/长度信息，因此不会误报死存储或越界。

### 4.2 表达式语句

单独一行写表达式是合法的，结果被丢弃：

```annota
noise + "y"        -- 允许，但不产生作用（分析器可能提示）
touch()            -- 常见用法：调用一个只有副作用的函数
```

### 4.3 条件

```annota
if cond( ... )
if cond( ... ) else ( ... )

-- elif 链，一行一个分支；`) elif`、`) else` 换行续写也合法
if score >= 90(
    = "A"
) elif score >= 60(
    = "B"
) elif score >= 30(
    = "C"
) else (
    = "D"
)
```

`if` 体是**括号块**，不是缩进块。条件中可用 `&&`、`||`、比较；`if`/`else` 可以嵌套。
`elif cond( ... )` 就是 `else if cond( ... )` 的写法（词法器把它当作同一个构造，只有一个语义）。

**分析器做分类讨论**：两侧都会带上各自的事实，并且**诊断会注明来自哪个分支**：

```annota
clamp(i)(
    if i < 1(
        i = 1
    )
    [[assert: i >= 1]]      -- 真分支给出 i = 1，假分支给出 i >= 1，并集仍是 i >= 1
    =i
)
```

* 真分支假设条件成立，假分支假设条件**取反**（`if i < 1` 的 else 路径知道 `i >= 1`）。
* 分支末尾直接返回/抛出/跳出的那一侧**不参与**后续状态的并集（`fib` 里 `if n < 2( =n )` 之后
  分析器知道 `n >= 2`，因此不会报 `n - 1` 溢出）。
* 分支里报出的每条诊断都会附带 "分支: 条件成立（i < 1）" 这样的说明，便于定位是哪条路径有问题。

### 4.4 循环

```annota
while i < n(
    i = i + 1
)

for x in xs( print x )              -- 列表 / 元组 / 字符串 / 字典 / 迭代器
for i in 0 to 9( print i )          -- 0..9（含 9）
for i in 0 to 9 step 2( print i )   -- 步长
for k, v in pairs(d)( print k, v )  -- 解构
```

`break` 提前退出，`continue` 进入下一轮。循环上可写 `[[invariant]]` 与 `[[decrease]]`。

### 4.5 返回、抛出、异常

```annota
add(a, b)( =a + b )          -- `= expr` 是 return

safe(x)(
    if x < 0( throw "negative" )
    =x
)

try_it()                     -- 可能抛异常
except e( print "caught: " + e )
```

`throw` 的参数会被包装成异常对象；`except` 必须紧跟在块之后（`except-placement` 检查）。

### 4.6 输入输出

```annota
print a, b, c                -- 空格分隔，自动换行
input name                   -- 读一行到 name（GUI 里弹对话框，见 README FAQ）
```

### 4.7 裸作用域

```annota
(
    new tmp = 1
    print tmp
)                            -- tmp 出了作用域即结束（读取会被 `scope` 检查报告）
```

## 5. 表达式

### 5.1 调用与具名参数

```annota
f(1, 2)
f(1, key = 2)                -- 具名参数用 `=`（组件属性同理：Text(text = "...")）
obj.method(1)
obj.field
xs[0], xs[i + 1]
```

### 5.2 函数定义

```annota
add(a, b) = a + b                    -- 单表达式（自动返回）
add(a, b)( =a + b )                  -- 块体
greet(name = "world") = "hi " + name -- 默认参数
total(*nums) = len(nums)             -- 可变参数（*args 与 ...args 等价）
```

可变参数收集成 `List`；**不支持 `**kwargs`**，需要键值对请显式传 `Dict`。
Lambda：`(x)( =x * 2 )`，可作为值传递。

### 5.3 闭包

函数捕获外层变量**按引用共享**（不是拷贝），因此：

```annota
counter()(
    new n = 0
    bump()(
        n = n + 1
        =n
    )
    =bump                 -- 返回的闭包与 n 共享同一个单元
)
```

需要各自独立的状态时，用类或每次显式拷贝一份。

### 5.4 分段表达式

```annota
new label = {
    score >= 90: "A"
    score >= 60: "B"
    else: "C"
}
```

分支按顺序判断；`else` 必需；分支之间用换行分隔。

### 5.5 转换与类型

```annota
int(x), float(x), str(x), bool(x)
typeof(x)                    -- "int" / "float" / "String" / "List" / "int8" ...
len(x), is_null(x)
```

**数值宽度（C 风格）**：宽度只在**声明或显式转换**时生效，未标注的整数保持解释器默认的 64 位
（`long`），因此旧代码行为不变。

| 类型 | 宽度 | 说明 |
|---|---|---|
| `int`（=`int32`） `long`（=`int64`） `int8` `int16` | 32/64/8/16 | 有符号 |
| `uint`（=`uint32`） `ulong`（=`uint64`） `uint8` `uint16` | 32/64/8/16 | 无符号，打印按无符号范围 |
| `float` | 32 | 每次运算后按单精度舍入 |
| `double` | 64 | 默认双精度 |
| `longlong` / `ulonglong` | 128 | 盒式存储，精确运算与回绕，打印走完整范围 |
| `longdouble` | 80 | 盒式存储，`longdouble(1)/longdouble(3)` 保留 18 位有效数字 |

```annota
new a:int8 = 200              -- 200 折回 int8：-56
print a + 100                 -- 44（与 int 混合时提升为 long）
print uint8(300)              -- 44
print uint64(0) - uint64(1)   -- 18446744073709551615
print int8(1) + int8(2)       -- 3，结果仍是 int8
print float32(1.0) / float32(3.0)   -- 0.3333333432674408
```

超大常量可以直接写：十进制/`0x`/`0o`/`0b` 字面量超出 64 位时自动成为 128 位值。

```annota
print 170141183460469231731687303715884105727          -- int128
print 0xFFFFFFFFFFFFFFFF + 1                           -- 18446744073709551616
print typeof(170141183460469231731687303715884105727)  -- "int128"
```

### 5.5b 定长 / 类型化数组

```annota
new a:int[5] = [1, 2]      -- 定长 5，自动补 0 -> [1, 2, 0, 0, 0]
new z:int[3]               -- 全部为 0
new m:int[3][4]            -- 连续存储的二维数组
m[1][2] = 7                -- m[1] 是行视图，写回父数组
new d:int[] = []           -- 带元素类型的可增长数组
d.push(1)
new names:string[3] = ["a"] -- 字符串元素补 ""
```

* 赋值与传参都是**深拷贝**（与其它值一致），行视图之外的写入不会互相影响。
* `len(a)` 是第一维长度；`for x in a` 遍历第一维（一维时是元素，多维时是行视图）。
* **越界**：分析器用静态长度证明 `a[5]`（长度 3）这类错误；运行时仍兜底检查。
* **省掉检查**：下标是**常量且静态在范围内**时编译器直接发未检查的索引；语句带已有的
  `[[unsafe]]` 提示时同样跳过运行时检查（不新增第二种标记）：

```annota
[[unsafe]]
hot(arr, i)( =arr[i] )     -- 你保证 i 合法，运行时不再比较
```

### 5.6 元组与解构

```annota
new pair = (1, "a")
new (a, b) = pair            -- 解构声明：括号里写名字
for k, v in pairs(d)( ... )  -- 循环变量同样可解构
```

### 5.7 切片（需 `use slice`）

```annota
use slice
xs[1:3]        -- 列表 → 只读 SliceView（.to_list() / len / 遍历）
xs[2:]  xs[:2]  xs[:]
text[2:5]      -- 字符串 → 字符串（"cde"）
```

切片是**编译期宏**展开，不是内建语法；没有 `use slice` 时 `xs[1:3]` 不可用。

## 6. 类

```annota
Point(x, y)=(
    X:int                     -- 声明字段（类型注解可选）
    Y:int
    tag = "p"                 -- 带默认值的字段

    __init__()(               -- 构造函数体：空括号，构造时执行
        X = x                 -- 读构造参数
        Y = y
    )

    norm2() = X * X + Y * Y   -- 方法
    [[static]]
    origin() = "0,0"          -- 静态方法：不绑定实例

    __str__() = "Point(" + str(X) + ", " + str(Y) + ")"
)

new p = Point(3, 4)
print p.norm2()
print Point.origin()
```

要点：

* 类名后的括号是**构造参数**；参数会自动成为同名字段（除非已声明同名字段）。
* `__init__` 必须**空括号**，在字段默认值之后执行，可覆盖默认值；给它参数是编译错误。
* 字段默认值在构造时求值；`X:int` 形式的字段默认 0。
* 魔法方法：`__str__` `__len__` `__iter__` `__call__` `__getitem__` 等，由运行期按名字调用。
* 继承：类体首行写 `:Base(args)`。

```annota
Dog(name)=(
    :Animal(name)             -- 调用基类构造
    speak() = "woof"
)
```

* 可见性标注：`[[private]]`（默认）、`[[public]]`、`[[static]]`、`[[expose]]`。

## 7. 视图与状态（GUI）

```annota
view Counter(title="Counter", width=400, height=300)(
    state count = 0

    inc()(
        count = count + 1
    )

    Column(pad=16)(
        Text(text="Count: " + str(count))
        Button(label="+1", click=inc)
    )
)
```

`view` 是特殊的类：外层 `state` 变化会触发界面重建；组件（`Column` / `Row` / `Text` /
`Button` / …）是内建构件。`annota <file> --gui` 打开窗口，IDE 里按 `F7` 预览。

## 7.5 符号化简（CAS）

分析器内部有一个很小的整数**线性式**化简器，把表达式规范成 `sum(k_i * v_i) + c`，因此可以
**证明**而不是猜测：

```annota
[[assert: i + 1 > i]]                    -- 差值恒为 1
[[assert: 2 * k == k + k]]               -- 差值恒为 0
[[assert: n - 1 < n]]
[[assume: x == 5]]
[[assert: x * 2 == 10]]                  -- 等式事实作为代入
```

它的能力分三层：

1. **等式与线性组合**：`==` 学到的等式作为代入（`[[assume: y == n + 1]]` 之后 `y - n == 1` 可证），
   `+`/`-`/常量乘除都参与规范化。
2. **区间推理**：把每个变量的**线性上下界**与抽象域的区间合起来算表达式的区间，于是
   `[[assume: n <= 1000 && i >= 0 && i < n]]` 能证明 `i + 1 <= n`、`i <= n - 1`、`2 * i < 2 * n`、
   `i - n < 0`、`i <= 999`（同一变量在两边的项会精确抵消，常量界则回灌进抽象域，溢出/下标检查
   也一起受益）。
3. **布尔结构**：`&&`、`||`、`!` 按三值逻辑组合；比较式会规范化成同一多项式的判定，因此
   `A || !A`（重言）、`A && !A`（矛盾）能被识别：

```annota
[[assert: (k < n) || !(k < n)]]          -- 重言
[[assert: !((k < n) && !(k < n))]]
```

这些结论同时加强了：`assert`/`require`/`ensure`/`invariant` 的证明、`redundant-condition`
（`if a + 1 > a` 会被指出恒为真）、`[[assume]]` 的矛盾检测（`annotation-argument`）以及数组下标的
静态越界证明。只有**精确**的线性/区间结论才会被采用，非线性或含未知量的比较仍交回抽象域，
因此不会产生误报。

## 8. 标注

标注是**规范**，放在它描述的单元之前：

```annota
[[module: math]]                 -- 元信息
[[version: 1.0]]
[[require: d != 0]]              -- 契约
[[ensure: result * d == n]]
[[invariant: i <= n]]            -- 循环
[[decrease: n - i]]
[[pure]]                         -- 无副作用
[[ignore: division-by-zero, "此处除零是刻意的"]]   -- 抑制一个检查
```

写在文件级（前后空行分隔）表示整个文件；写在函数/类/循环/语句前表示该单元。完整列表与含义见
[reference.md](reference.md) 第 1 节。

## 9. 模块

```annota
use seq              -- lib/ 或当前目录下的 seq.mod
use sub/几何          -- 路径写法：sub/几何.mod（也接受 `use "sub/几何"`）
use seq.mod          -- 带后缀
use math             -- 原生模块（C++ 实现，内置）
use hello            -- 插件模块：自动加载 hello.dll / libhello.so（见 docs/ffi.md）
```

* **搜索路径**：主文件所在目录、该目录的 `lib/`、`lib/`、当前目录、**解释器所在目录**及其
  `lib/`、`../lib`；每个被加载模块所在目录也会加进来，因此模块可以 `use` 自己的兄弟模块
  （子目录模块也没问题）。所以从任意工作目录启动（包括图形界面）都能找到标准库。
* **插件**：如果既不是脚本模块也不是内置模块，`use` 还会去 `<解释器目录>/plugins/` 和
  `./plugins/` 找 `<名字>.dll` / `lib<名字>.so` 并加载（`annota plugin build` 就是生成它的
  命令）。静态分析器加载同一份插件，所以 `use <插件>` 不会报未定义。
* **`use` 是幂等的**：同一个模块重复 `use` 只会加载一次；互相 `use`（a ↔ b）也不会无限递归。
* **找不到模块会报错**，并给出可操作的提示（搜索过哪里、有哪些模块、最接近的名字）：

```
error: cannot find module 'seqq' (searched build, build/lib, lib, .)
  available modules: dict, geometry, graph, mathx, matrix, numeric, ...
  did you mean 'seq'?
```

* **模块顶层的东西是程序全局**：`use` 会把模块语句内联到当前程序，因此模块里 `new` / `const` 声明的
  变量、函数、类、宏在主文件里可以直接用；运行时的行为和静态分析器看到的一致。
* 模块内部的诊断默认不报到主文件（它们属于模块自己的文件），加 `--modules` 可以让分析器连模块内部
  的检查一起报出来（用于开发标准库本身）。
* 标准库总览见 [stdlib.md](stdlib.md)，模块一览见 [README](../README.md#standard-library)。

## 10. 宏

```annota
macro twice($x)(
    $x + $x                      -- $x 是占位符，匹配调用处的任意片段
)
print twice(3)                   -- 展开成 3 + 3

macro $x[$a:$b](                 -- 模式宏：匹配 xs[1:3] 这样的下标写法
    Slice.make($x, $a, $b)
)
```

`[[jit]]` 表示"这个函数**在加载期**就编译"：先做超指令融合，能整体翻译成机器码就翻译，语义
不变、只影响性能。**不写标记也会优化**——解释器会给热循环自动提升（见 [jit.md](jit.md)），
`[[jit]]` 只是把时机提前，不存在第二个同义标记。

```annota
[[jit]]
sum_to(n)(
    new s = 0
    new i = 0
    while i < n( s = s + i, i = i + 1 )
    =s
)
```

`macro` 后的整段 token 是**模式**，`$名字` 是占位符；括号里是展开后的代码。
宏在编译期展开，参数是**语法片段**而非值。展开深度上限由 `[[macro_depth: N]]` 控制
（默认见实现），超过会报 `Macro expansion depth exceeded`。实参在宏体里出现多次时，
分析器会用 `macro-side-effect` 提醒可能的重复求值。

## 11. 与文档取舍的地方

以下是实现中明确选择的语义，写代码时按这些来：

1. **没有 `main`**：顶层即入口。
2. **括号块而非缩进块**：`if c( ... )`、`f(a)( ... )`。
3. **`else` 必须与 `)` 同行**。
4. **`/` 是 C 语义**：整数相除向零截断，浮点除法需要至少一个浮点操作数。
5. **字符串按字节索引**，长度是字节数。
6. **`substr(start, stop)` 的第二个参数是结束下标**（Python 风格），不是长度。
7. **语句不能跨行**，除 §1.2 的三种续行方式。
8. **闭包按引用捕获**，工作线程里要注意共享状态（见 README「原语」一节）。
9. **`**kwargs` 不支持**，用 `Dict`。
9b. **超过 64 位的字面量是 128 位**（`int128`），字面量本身不回绕。
10. **切片依赖 `use slice`**（宏实现）。
11. **容器按值传递**：赋值、传参、返回都深拷贝；要共享必须用 `lend`（§4.1.2）。
12. **性能优化不改变语义**：热循环会被自动编译成机器码，`[[jit]]` 只是"加载期就编译"；
    关掉它的开关见 [jit.md](jit.md)。
